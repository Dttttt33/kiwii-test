# Kiwii 体测站 设计原则

适用范围：从 P1 欢迎页到 P17 训练计划，整站通用。
每次改页面内容前先对照这份文档。

---

## 1. UX 原则（用户旅程的情绪设计）

### 核心基调

**鼓励的、亲切的、有趣的，但不幼稚。**

用户从头到尾应该觉得：有人在陪我、有人懂我、接下来的事情我做得到。

### 情绪弧线

| 阶段 | 页面 | 用户情绪目标 |
|------|------|-------------|
| 破冰 | P1-P4 | 放松、好奇、"这个不难" |
| 体测 | P5-P13 | 投入、被引导、"跟着做就好" |
| 揭晓 | P14 | 惊喜、被看见、"原来我的身体是这样的" |
| 方向 | P15 | 信任、期待、"这些目标我想要也做得到" |
| 承诺 | P16 | 仪式感、画面感、"我愿意开始" |
| 出发 | P17 | 行动力、安心、"我知道第一步是什么" |

### 安全感原则

每一页都要让用户对"接下来会发生什么"有预期：
- 标题告诉用户这步在做什么
- 小鸟预告接下来会怎样 / 为什么要做这一步
- 不让用户猜、不让用户紧张

### 选择题不预设答案

需要用户主动选择的选项（年龄、性别、运动经验等），**不能有默认选中状态**。
- 默认选中 = 暗示"这是正常的"，其他选项变成"偏离"
- 用户可能直接跳过而没有真正做选择，导致数据不准
- 唯一例外：明确的"安全缺省"（如 痛点页的"没有，都还不错"）

### 体验红线（绝对不能出现的）

- 让用户觉得自己"差"或"不行"
- 让用户觉得在和机器对话
- 让用户需要思考"这是什么意思"
- 信息过载——一屏塞太多东西
- 前后不呼应（P15选的东西P16没体现）
- Intrusive 的问法——像面试官在审问（"你平时运动多吗"）
- 暴露系统内部逻辑给用户（"用来估算初始阻力"）

## 2. UI 原则

### 核心美学：任天堂感

- **字少**：每个元素的文字能少一个字就少一个字
- **空间大**：留白是信息的一部分，不是浪费
- **视觉优先**：能用颜色/图形/大小表达的，不用文字
- **不堆文本框**：避免"表单感"和"文档感"
- **一眼抓重点**：每页有且只有一个核心信息，3秒内能get

### 硬约束：横屏电视投屏

- **不能滚动**：每一页所有内容必须在一屏内完整显示（viewport height）
- **横屏比例**：16:9 或类似，内容必须利用水平空间
- **不能大面积留白**：左右不要出现"窄条居中"的排布，内容要撑满或用左右分栏
- **一页信息不能太多**：如果一页塞不下就拆成两页，宁可多一步也不要挤

### 排布规则

- 内容水平撑开，利用横屏空间（左右分栏 > 单列窄居中）
- 信息层级用大小区分，不用"标签+内容"的表单结构
- 按钮要大、要明确、一个页面最多2个选择
- 卡片之间留足间距
- 小鸟永远在它关联内容的容器里面，不游离在外
- 每页高度 = 100vh，禁止出现纵向滚动

### 进度条

- 顶部进度条保留现有样式
- 关键节点（体测开始★、结果揭晓★）有标记
- 当前步骤高亮，已完成变色

## 3. 文案原则（Wording）

### 调性：任天堂感

像 Animal Crossing 的对话框。短句、有节奏、让人忍不住微笑、说的是有用的事但让人觉得被照顾。

### 硬性规则

| 规则 | 说明 |
|------|------|
| 不出现分数/数字 | 用户不需要被量化评判 |
| 不做无法做的判断 | 一次体测不能说趋势（"越来越松"）、不能说因果（"因为你久坐"） |
| 不居高临下 | 不说"我已经看到了""我知道你需要"——这不是用户想听到的 |
| 不说负面词 | 不说"差""弱""不行""费力""吃力""偏紧""偏弱""容易累"，永远用正面/鼓励表达 |
| 用身体感受说话 | 不用抽象概念（"稳定性""心肺功能"），用"弯腰""爬楼""提东西"这种具体动作 |
| 句子短 | 一句话不超过15个字。能用一句说完的不用两句 |
| 不重复 | 同一页不出现相同的句式结构 |
| 不人机 | 不说"根据你的数据""系统建议""检测到"这类词 |
| 不暴露逻辑 | 不跟用户解释为什么要收集这个信息 / 内部怎么处理 |

### 标题原则

- 标题 = 告诉用户这一步在做什么（简洁、行动导向）
- 不用问句审问用户（"你平时运动多吗"❌）
- 不用"让我看看""我来认识你"这种小鸟才说的话放在标题

### 小鸟说话原则

**语气 = 温暖教练 + 可爱同伴**

- 专业但不居高临下——它懂身体，但它和你是平等的
- 短句有节奏，偶尔俏皮
- 每一句都有信息量/有用，不废话不客套
- 不评判、不说教
- 可以偶尔用语气词（"嘿""不错哦"）但不过度

**小鸟话的功能 = 给用户安全感和预告**

- 告诉用户"接下来会发生什么"，让人有心理准备
- 不暴露内部逻辑（不说"用来估算阻力""根据你的数据""我会自己感受的"）
- 不 intrusive / 不审判
- 标题说做什么，小鸟说为什么 / 会怎么样——两者配合
- 不说空洞的鼓励话（"很快的""随便选"）——要有具体信息

## 4. 定制化原则

### 核心

**用户做完体测后，后面每一句话都应该让人觉得"这是写给我的"。**

### 输入变量（全部参与文案定制）

| 变量 | 来源 | 影响范围 |
|------|------|---------|
| 年龄 | P2 | 场景选择、语气、目标描述 |
| 性别 | P2 | 动作示范 |
| 身高 | P2 | 体重判断的基准 |
| 体重 | P2 | 影响 tag、解读、目标（偏重/偏轻的人文案不同） |
| 运动经验 | P3 | 初始阻力 + 解读第1句 + "新手进步快"相关文案 |
| 痛点/不适 | P4 | comfort 目标文案 + 保护策略 |
| 活动度分数 | 体测 | tag、解读、目标、promise |
| 稳定度分数 | 体测 | tag、解读、目标、promise |
| 力量分数 | 体测 | tag、解读、目标、promise |
| 心肺分数 | 体测 | tag、解读、目标、promise |

**定制化不是三分法。** 每条文案基于多个变量组合判断，不是简单的 high/mid/low。同一个 70 分的力量，新手和停练者、体重大和体重轻的人，看到的话应该不一样。

### P4 身体照顾页的设计意图

**情绪 = caring，不是问诊。** 这页的 tone 是"我关心你"，不是"你哪里有问题"。

**覆盖范围：**
- 身体区域（泛的，不是精确关节）：肩颈、腰部、髋/骨盆、膝盖、手肘手腕、脚踝
- 特殊状态：孕期或产后
- 兜底：其他（开放填写）
- 安全缺省：「没有，状态不错」默认选中

**设计意图：**
- 用户选的区域 = 训练时**着重照顾**（减轻负荷、避开特定动作模式）
- 不是"绕开"——文案 = "训练时我会绕开或减轻这些区域的压力"
- 特殊状态（孕产）= 限制高强度、俯卧动作、tier 3 动作全部锁住

**保护策略对应：**

| 选择 | 编排保护 |
|------|---------|
| 肩颈 | 排除 push 类、过顶动作；增加恢复和活动度站 |
| 腰部 | 排除硬拉/挺身/俯身/伐木；增加恢复站+躯干稳定 |
| 髋/骨盆 | 排除深蹲/弓步/硬拉；增加活动度+恢复 |
| 膝盖 | 排除蹲/弓步/跪起；增加恢复站 |
| 手肘手腕 | 排除弯举/推举类；减少上肢权重 |
| 脚踝 | 排除蹲/弓步/单腿；增加活动度 |
| 孕期或产后 | 排除俯卧/卷腹/硬拉/过顶/tier3；大幅增加恢复+活动度；降低代谢和全身训练权重 |

### 定制化在各页面的体现

**P14 能力卡**
- Tag：4个象限各自根据分数段显示不同的身体感受词（确认版见下方）
- 小鸟4段解读：每段都根据哪项最强/最弱动态变化
- 点击单张卡的详细解读：根据该项分数段给不同的文案

**P15 目标选择**
- 6个目标的主标题和副标题全部基于当前分数段定制
- 高分维度 → 目标 = 维持（但包装成正面的、aspirational的）
- 低分维度 → 目标 = 当前 + 15%（一个可达成的提升）
- 推荐3个 = 分数最低的3个维度

**P16 约定页**
- Promise 列表 = 用户在P15选的目标标题（直接对应，不能断联）
- 时间线预期根据用户选的频率动态调整

**P17 训练计划**
- 课程编排基于选定目标和体测分数
- 动作选择、区域分配、负重都和输入相关

## 5. 目标设定原则（P15 专项）

### 核心逻辑

6个维度，每个维度的目标 = **用户当前状态 + 15% 的提升**。

- 当前很强（≥76）→ 目标 = 维持这个好状态（但要包装得 aspirational）
- 当前一般或偏弱（<76）→ 目标 = 一个稍微够一够就能达到的提升

### 6个维度

| 维度 key | 对应分数计算 | 代表什么 |
|----------|-------------|---------|
| shape | (力量+活动度)/2 | 体态/线条 |
| lean | 四项平均 | 轻盈度/体重管理 |
| strength | 力量分 | 日常力量 |
| sport | (稳定度+心肺)/2 | 运动耐力 |
| energy | 心肺分 | 全天精力 |
| comfort | (活动度+稳定度)/2 | 身体舒适度 |

### 目标文案标准

**主标题**：简短状态描述（4-8字）
- 让人一看就知道"我会变成什么样"
- 不是动词开头的口号，是一个状态
- 例：「下半身更有力」「一天精力更长」「体态更挺拔」

**副标题**：一个具体的生活场景（一句话）
- 让人能想象到那个画面
- 必须是这个人生活中真实会遇到的场景
- 根据年龄/性别选择不同场景
- 例：「上三层楼还能边走边聊天」「坐了一下午站起来腰背不紧」

### 目标文案红线

- 主标题不能让人"看不懂"
- 副标题必须和主标题对应（不能主标题说力量，副标题说柔韧）
- 不出现"维持""保持"这种无聊的词——即使是维持类目标也要包装成 aspirational
- 每个目标必须同时满足：**具体 + aspirational + 可实现（1-3个月）**

## 6. P14 能力卡 详细规范

### Tag（5 档）

Tag = 能力象限 × 当前程度，3-7字，每档正面、有性格。

| 能力 | ≥85 | 76-84 | 65-75 | 50-64 | <50 |
|------|------|-------|-------|-------|-----|
| 动作自由度 | 柔软度王者 | 活动度超赞 | 还能更舒展 | 慢慢松开中 | 等待解封 |
| 身体稳定度 | 稳如泰山 | 平衡感在线 | 越来越稳 | 稳定修炼中 | 摇摇晃晃也可爱 |
| 力量表现 | 大力士就是你 | 力量充足 | 力气在涨 | 力量觉醒中 | 蓄力准备中 |
| 体能续航 | 精力充沛王者 | 续航能力强 | 耐力在线 | 体能充电中 | 电量待补充 |

**Tag 原则**：
- 必须同时体现"哪个能力象限" + "当前程度"
- 每一档都是正面表达，低分也不能让人觉得差
- 有性格感——像游戏里的称号，让人愿意展示
- 不用"还行""够用""偏紧""偏弱"这种含糊/负面的词

### 小鸟 4 段解读（已确认结构）

结构：**总 → 感受 → 机会 → 邀请**

1. **总**：一句温暖的整体肯定（根据运动经验和整体水平定制）
2. **感受**：你身体现在强的地方是什么感觉（对应最强项，用具体身体感受）
3. **机会**：最容易看到进步的方向（对应最弱项，用正面语言说"可以更好"）
4. **邀请**：跟 Kiwii 练会是什么样（训练均衡不偏科，给一个期待画面）

**解读红线**：
- 不说"站不太稳""力量一般"——68分不是"差"，表述要精确匹配程度
- 不做超出体测能力的判断（不说趋势、不说原因）
- 训练描述必须是全面的（不是只练某一项）

## 7. P16 约定页

### 原则

- Promise 列表 = P15 每个选中目标的 **detail（场景文案）**，不是 title
  - 例：选了"下半身更有力" → promise 显示"提东西上楼不费劲"，不是"下半身更有力"
  - 这层包装让 promise 读起来 aspirational 和 personal
- 整体字少、空间大
- 有仪式感但不厚重
- 小鸟在内容区域里面
- 不出现数字（"动作自由度目前20，目标35"❌）
- 按钮文案 = "开始冒险" 或同等行动感的 wording

## 8. P17 冒险地图（训练编排）

### 进入体验

1. **数字动效**：进入时从 1 快速跳到 40，让用户感受到计划的规模
2. **小鸟一句话**："已经根据你的体测结果定制好了专属计划，点一站看看里面有什么"
3. **地图展开**：横向可拖拽路径，每屏 3-4 个岛屿节点，不规则圆角造型

### 核心编排逻辑

**10 个冒险区域**（farming 主题命名，每个区域有独立的动作角色序列）：

| 区域 | 侧重 | 颜色 | 角色序列 |
|------|------|------|----------|
| 根基田 | 臀腿力量 | #6fba2c | anchor → mobility → anchor → stability |
| 独木桥 | 单腿稳定 | #8ac68a | stability → anchor → mobility → control |
| 渔获湾 | 背部拉力 | #82d5bb | pull → pull → accessory → control |
| 石磨坡 | 胸肩推力 | #889df0 | push → push → accessory → mobility |
| 谷仓 | 躯干稳定 | #fc736d | control → stability → control → mobility |
| 风车岭 | 转身传力 | #e59266 | rotation → control → stability → rotation |
| 丰收集 | 全身配合 | #57cdbd | anchor → power → pull → control |
| 麦浪道 | 耐力节奏 | #f7cd67 | power → anchor → power → control |
| 温室 | 活动舒展 | #b77dee | mobility → control → mobility |
| 树荫亭 | 轻松恢复 | #d4c9b4 | control → mobility → stability |

### 定制化输入 → 编排输出（8 个 input 各自独立作用）

| 输入 | 影响什么 | 怎么影响 |
|------|---------|---------|
| 年龄 | 阻力 × ageFactor, 动作数, reps 上限 | 55+: ×0.7, max 10reps, 3动作/站; 45: ×0.85; 35: ×0.95 |
| 性别 | 阻力 × genderLoadFactor | 女性 ×0.75 |
| 体重/身高 (BMI) | 阻力 × weightFactor | BMI>30: ×0.85; BMI<18.5: ×0.9 |
| 运动经验 | 阻力 × expFactor, 动作池 tier 门槛 | 刚开始 ×0.6; 老手了 ×1.1 |
| 体测力量基准 (VBT) | 阻力基准值 squatLoad | 所有 load 计算的起点 |
| 体测各项分数 | 动作难度 tier 解锁, 编排策略 | stability<55 → 减少单腿; mobility 低 → tier-3 mobility 动作锁住 |
| P4 痛点部位 | 排除对应动作 / 增加恢复站权重 | 直接从候选池移除 |
| P15 选择的目标 | 10 个区域的分配比例, reps 策略 | 减脂 → +2reps; 力量 → 力量区域 +5权重 |
| 装备轮换 | 偶数站 T-Bar，奇数站 Single Handle | - |

### 阻力公式

```
load = squatLoad × ageFactor × genderFactor × weightFactor × expFactor × roleRatio × hardwareFactor × orderFactor × progressionMultiplier
```

### 动作解锁逻辑

每个动作有 tier (1/2/3)。是否解锁取决于该动作对应身体区域的体测分数 + 训练进度：
- tier 1: 始终可用（深蹲、坐姿划船等基础动作）
- tier 2: 对应区域分数 ≥ 45 或进度补偿后达到（俯身划船、弓步等）
- tier 3: 对应区域分数 ≥ 65 或进度补偿后达到（鸟狗划船、平板划船等）
- advanced: 仅站 20 之后解锁（复合连续动作）

### 站点结构 (40 站 = 39 训练 + 1 体测)

- **站 1-19**：基础动作库（48 个动作，不含高阶复合动作）
- **站 20**：丰收体测日（第二次体测，milestone 节点）
- **站 21-40**：解锁高阶动作库（+13 个复合/旋转动作）

### 渐进难度

- 阻力：loadMultiplier 从 1.0 渐增至 1.35（线性 i/39）
- 次数：baseReps 从 6 渐增至 10，上限 12
- 时长目标：从 ~6min 渐增至 ~8min
- 第 40 站不会 super 难——progression 上限 = 1.0，loadMultiplier 上限 = 1.35

### 安全编排规则

1. **动作压力碰撞检测 (clashes)**：相邻动作不能共享 lumbar/shoulder/balance 压力标签；lumbar 后不接 rotation；floor 后不接 power；单侧动作不能连续出现（压力太大）
2. **姿态高度排序**：同一站内动作按姿态从低到高排列（俯卧 → 跪姿 → 坐姿 → 俯身/屈髋 → 弓步/分腿 → 站姿），不能中-高-低跳来跳去
3. **痛点保护**：有标记部位的动作直接排除或降级阻力
4. **区域排序**：相邻站不同区域，不同 zone（lower/upper/core）；高强度站后接恢复/活动度站
5. **时间拟合 (fitSequence)**：默认 2 轮，超时则先减 reps → 再减动作数 → 最后减至 1 轮；不足 5min 则加 reps
6. **单侧动作**：自动识别，reps 计算 ×2（左右各一边），preview 标注"换边"

### 站点 Preview

点击任意站点弹出底部卡片：
- 标题：第 N 站 · 区域名
- 3 个 tab：训练部位 / 配件 / 时长+轮数
- 每个动作：名称 + 阻力kg + 次数 + 是否换边

## 10. 训练编排铁律（sequence 规则）

### 姿态高度排序

同一站内所有动作必须**从低到高**排列（不能高-低-高跳跃）：

| 姿态 | 高度值 | 示例 |
|------|--------|------|
| 俯卧/仰卧 | 1 | 俯卧下拉、平板支撑划船 |
| 跪姿 | 2 | 跪起托盘推举、半跪姿拔剑 |
| 坐姿 | 3 | 坐姿划船、坐姿卷腹 |
| 俯身/屈髋 | 4 | 俯身划船、硬拉、早安式 |
| 弓步/分腿 | 5 | 弓步蹲、侧弓步 |
| 站姿 | 6 | 深蹲、过顶推举 |

### 单侧动作分散

- 一个 sequence 里不能连续两个单侧（Single Handle unilateral）动作
- 压力太大 → 必须穿插双侧动作隔开
- 低 stability 的用户（<55分）进一步减少单侧动作总数

### 压力碰撞检测

相邻两个动作不能共享相同的压力标签：
- lumbar 后不接 lumbar（也不接 rotation）
- shoulder 后不接 shoulder
- balance 后不接 balance
- floor 后不接 power（姿态差太大）

### 时间拟合（1 动作 = 10 秒）

- 默认 2 轮，时间目标 6-8 分钟
- 超时：先减 reps → 减动作数 → 减至 1 轮
- 不足：加 reps（不超上限）
- 单侧动作 reps ×2（左右各一边）
